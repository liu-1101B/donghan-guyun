# 逐音素合成验证报告（学者拟音 → 音频）

> 生成日期：2026-10-31 · 脚本 `scripts/phoneme_verification_report.py`（重跑即再生）
> 数据：`data/historical/sinica_ccr_import/`（Sinica CCR 11 家学者体系）+ 东汉实验字表（703 字，`phonology_db.EASTERN_HAN_DB`）。
>
> **核心口径：「有音频输出」≠ 成功。** 引擎对一条读法的处置分档：
> `full` 全部音素按预期合成；`approx` 段完整但个别音素近似（重音/音色丢失）；
> `partial` 有音素被引擎**静默丢弃**（音节缺段，音频比读法短）；
> `untested` 含未实测音素（不保证）；`silent` 整条无声。
> 能力矩阵来自 `language/phoneme_capability.py`（eSpeak-ng 1.52 -v zh
> 2026-10-30 逐符号实测冻结集合），矩阵只保证「该段有声音」，不保证听感正确。

## 四、边界与如实声明

1. `approx` 只保证「有声音」，不保证听感正确（重音/音色丢失是已知损失）。
2. `untested` = 不在 2026-10-30 实测冻结集合里的符号，发声与否不保证；
   若表中出现 >0，说明数据里出现了新符号，应补测后更新冻结集合。
3. `no_ipa_records`（缺 IPA 行）= 上游源表缺陷（声母列含汉字/元音开头/
   只剩送气符），加载时如实标记 suspect、不生成 IPA、不参与合成。
4. 共振峰引擎只是 eSpeak 整体失败时的回退，其 partial/silent 占比
   不代表主路径质量。
5. 本报告是数据快照；Sinica 数据包或能力冻结集合变化后重跑本脚本。
6. 逐音素矩阵的 token 粒度 = `sound_synth.tokenize_ipa` 的切分
   （如 `tɣ`、`i̯uŋ`），与引擎实际送读单位一致。
